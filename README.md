# TeslaCraft Parser

Программа собирает открытую статистику игроков, наказаний, кланов и форума
[TeslaCraft](https://teslacraft.org) и показывает результаты в удобном
настольном интерфейсе.

Для повседневного использования команды и знание Python не нужны — достаточно
запустить `TeslaCraftParserGUI.exe`.

## Быстрый старт

### Если у вас уже есть готовая программа

1. Откройте `TeslaCraftParserGUI.exe`.
2. Слева выберите **Сбор данных**.
3. В поле **Что собрать** выберите нужный вариант.
4. Прочитайте появившееся пояснение и при необходимости измените параметры.
5. Нажмите **Запустить**.

Откроется обычное окно Google Chrome. Если сайт покажет проверку Cloudflare,
пройдите её вручную и ничего больше не нажимайте в программе — сбор продолжится
автоматически.

Во время работы можно нажать **Пауза** или **Остановить**. Уже полученные данные
не пропадут.

### Если вы скачали исходный код

Понадобятся Python 3.12+ и установленный Google Chrome:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe main.py
```

## Какой режим выбрать

| Режим | Для чего он нужен | Пример результата |
|---|---|---|
| **Игроки и рейтинги** | Ники, даты регистрации и три вида рейтинга игроков | Топ положительного рейтинга |
| **Наказания** | Актуальные баны, кики, муты и предупреждения | Наказания выбранного игрока за период |
| **Исторические баны** | Старые карточки банов по числовым ID | Архив статусов старых банов |
| **Кланы** | Кланы, их участники и очки | Общий рейтинг игроков по клановым очкам |
| **Раздел форума** | Темы конкретного раздела, префиксы и активность | Самые просматриваемые темы и топ авторов |
| **Карта форума** | Все категории, разделы и подразделы | Список доступных разделов со ссылками |
| **Апелляции** | Апелляции, которые ещё не получили итоговый префикс | Список тем без префикса |
| **Комплексный запуск** | Несколько основных сборов по очереди | Единая заполненная база |

После выбора режима интерфейс показывает:

- что именно будет открываться на сайте;
- какие результаты появятся;
- какие параметры особенно важны для этого режима.

## Основные параметры простыми словами

### Последний ID или последняя страница

Если оставить поле пустым, программа попробует определить границу
автоматически. Для первого знакомства лучше указать небольшой диапазон вручную.

### Только списки, без подробных страниц

Программа соберёт общую таблицу, но не будет открывать каждую найденную карточку
или страницу темы. Такой запуск заметно быстрее и хорошо подходит для проверки.

### Обновить уже сохранённые записи

Обычно программа пропускает то, что уже успешно получала. Эта галочка заставляет
её заново проверить записи и сохранить изменения.

### Создать снимок

Сохраняет состояние выбранного набора данных на текущий момент. Позже в разделе
**Снимки** можно увидеть, какие записи появились, изменились или исчезли.

### Одновременных страниц

Безопасное значение — от 3 до 5. Большее число может ускорить сбор, но сильнее
нагружает сайт и чаще приводит к повторной проверке Cloudflare.

## Где смотреть результаты

В интерфейсе откройте **Данные и аналитика**. Там можно:

- выбрать собранный набор данных;
- посмотреть общую статистику и диаграмму;
- просмотреть первые 100 записей;
- экспортировать весь выбранный набор в CSV;
- перенести в новую базу старый JSONL-файл.

При запуске готового `.exe` результаты по умолчанию находятся в
`%LOCALAPPDATA%\TeslaCraftParser\results`. Точный путь всегда виден и меняется в
разделе **Настройки**. При запуске из исходного кода используется папка `results`
в каталоге проекта.

Внутри папки результатов находятся:

- `teslacraft.db` — основная база данных;
- `*.jsonl` — совместимые структурированные выгрузки;
- `*.txt` — простые читаемые отчёты и рейтинги;
- `*_errors.jsonl` — страницы, которые не удалось получить;
- `exports` — CSV-файлы, созданные через интерфейс.

## Что происходит при повторном запуске

Программа не начинает всё заново. Она видит сохранённые записи, пропускает уже
готовые страницы и продолжает с отсутствующих. Это позволяет безопасно:

- остановить долгий сбор;
- закрыть программу после ошибки сети;
- перезагрузить компьютер;
- повторить ту же задачу позже.

Чтобы намеренно проверить старые записи повторно, включите **Обновить уже
сохранённые записи**.

## Частые вопросы

### Появилась проверка Cloudflare

Пройдите её самостоятельно в открывшемся Chrome. Программа не решает CAPTCHA и
не пытается обходить защиту автоматически — она только ждёт подтверждения.

Cookies сохраняются в отдельном профиле `user-data` рядом с папкой результатов,
поэтому при следующих запусках проверка обычно появляется реже. Точный путь
показан в **Настройках**.

### Программа пишет, что новых элементов нет

Все элементы выбранного диапазона уже есть в базе. Укажите другой диапазон или
включите обновление сохранённых записей.

### Сбор идёт слишком долго

Для пробного запуска:

- укажите одну последнюю страницу;
- включите **Только списки**;
- задайте ограничение карточек;
- сократите диапазон ID.

### Chrome был закрыт или пропал интернет

Запустите ту же задачу повторно. Уже сохранённые результаты останутся на месте.

### Можно ли запускать два экземпляра одновременно

Не рекомендуется использовать один и тот же профиль `user-data` в двух
процессах. Chrome может заблокировать профиль, а параллельные сборы создадут
лишнюю нагрузку на сайт.

# Для опытных пользователей

## Что умеет парсер

- автоматическое определение последнего ID игрока или бана;
- фильтры наказаний по нику, блюстителю, дате и статусу;
- четыре вида наказаний: бан, кик, мут и предупреждение;
- динамические префиксы форума по названию или ID;
- объединение нескольких префиксов и тем без префикса;
- автор, дата, ответы, просмотры, последний автор, закрепление и блокировка темы;
- SQLite, снимки, сравнение изменений, CSV и импорт JSONL;
- пауза, контролируемая остановка, повторные попытки и предварительный план;
- HTML-фикстуры и автоматические тесты без обращения к TeslaCraft.

## Консольный режим

Полная справка:

```powershell
.\.venv\Scripts\python.exe usersparser.py --help
```

### Игроки

Последний ID можно не указывать:

```powershell
.\.venv\Scripts\python.exe usersparser.py members
```

Явный диапазон и обновление сохранённых карточек:

```powershell
.\.venv\Scripts\python.exe usersparser.py members --start-id 1 --end-id 150000
.\.venv\Scripts\python.exe usersparser.py members --start-id 149000 --end-id 150000 --refresh
```

### Наказания

```powershell
.\.venv\Scripts\python.exe usersparser.py punishments --type ban --type mute --since 2026-01-01 --until 2026-07-31 --status "Активен"
```

Поиск, который предоставляет сам сайт:

```powershell
.\.venv\Scripts\python.exe usersparser.py punishments --nick "Toshka"
.\.venv\Scripts\python.exe usersparser.py punishments --moderator "T-b" --index-only
```

### Кланы и форум

```powershell
.\.venv\Scripts\python.exe usersparser.py clans
.\.venv\Scripts\python.exe usersparser.py sections
.\.venv\Scripts\python.exe usersparser.py forum --forum-url "https://teslacraft.org/forums/Прочие-баги.44/"
```

Префиксы считываются с выбранного раздела, а не зашиваются в программу:

```powershell
.\.venv\Scripts\python.exe usersparser.py forum --forum-url "https://teslacraft.org/forums/Прочие-баги.44/" --prefix "Исправлено" --prefix "Не баг" --without-prefix --index-only
```

### План без запуска Chrome

```powershell
.\.venv\Scripts\python.exe usersparser.py members --end-id 150000 --dry-run
```

## SQLite, снимки и CSV

При запуске из исходного кода основная база по умолчанию:
`results\teslacraft.db`. Готовый GUI использует пользовательскую папку, описанную
выше. Каждый вид и набор фильтров
имеет своё пространство имён, например:

- `members`;
- `bans:historical`;
- `clans:details`;
- `forum:Прочие-баги.44:index`.

Создание снимка:

```powershell
.\.venv\Scripts\python.exe usersparser.py members --snapshot
.\.venv\Scripts\python.exe usersparser.py clans --snapshot weekly
```

Список и сравнение снимков:

```powershell
.\.venv\Scripts\python.exe usersparser.py snapshots
.\.venv\Scripts\python.exe usersparser.py snapshots --compare 1 2 --json results\difference.json
```

Экспорт CSV:

```powershell
.\.venv\Scripts\python.exe usersparser.py export --namespace members --csv results\exports\members.csv
```

Перенос старого JSONL:

```powershell
.\.venv\Scripts\python.exe usersparser.py migrate --namespace members --jsonl results\old_members.jsonl --key-field id
```

## Устройство хранения и обработка ошибок

SQLite хранит актуальное содержимое записи, время первого и последнего
обнаружения, время последнего изменения и связь с запуском. После каждого пакета
транзакция завершается, а совместимые JSONL/TXT-отчёты обновляются атомарно.

Исправлены проблемы прежних вариантов парсера:

- вместо таймаута локатора в 10 мс используется единый настраиваемый таймаут;
- после неудачного перехода не разбирается содержимое предыдущей страницы;
- повторные попытки выполняются с увеличивающейся паузой;
- файлы не очищаются при старте;
- обе границы диапазона ID включаются в обработку;
- остановка не уничтожает уже записанные результаты;
- клановый обход поддерживает ограничение, паузу и штатную остановку;
- критичные HTML-парсеры проверяются локальными фикстурами.

## Сборка Windows

Собрать оба проверенных `.exe` и удалить промежуточные файлы:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

Результат:

- `dist\TeslaCraftParserGUI.exe` — графический интерфейс;
- `dist\TeslaCraftParser.exe` — консольный single-file вариант.

### Только GUI EXE

```powershell
.\.venv\Scripts\flet.exe pack main.py --icon assets\icon.ico --name TeslaCraftParserGUI --distpath dist --product-name "TeslaCraft Parser" --product-version 2.0.0 --file-version 2.0.0.0 --add-data "assets:assets" ".venv\Lib\site-packages\patchright\driver:patchright\driver" --hidden-import patchright.async_api --yes
```

### Только консольный EXE

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean UsersParser.spec
```

### Нативный Flutter bundle

```powershell
.\.venv\Scripts\flet.exe build windows --yes
```

Для этого варианта нужны Visual Studio с компонентом **Desktop development
with C++** и доступ к загрузке Flutter. На Windows также может потребоваться
Developer Mode для символических ссылок. Обычная сборка через `flet pack` этих
компонентов не требует.

На компьютере, где запускается любой собранный вариант, должен быть установлен
Google Chrome.

## Проверки разработки

```powershell
.\.venv\Scripts\ruff.exe check teslacraft_parser tests main.py usersparser.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

GitHub Actions выполняет эти проверки на Windows без обращения к TeslaCraft.
Тестовая HTML-разметка находится в `tests\fixtures`.

## Рекомендуемая нагрузка

По умолчанию используются пять одновременных страниц и пауза 0,25 секунды между
пакетами. При частых проверках Cloudflare уменьшите параллельность до 3,
увеличьте паузу и отложите следующий запуск.
